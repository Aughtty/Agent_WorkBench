# 14 天可投递冲刺计划

每天同时包含知识、开发和面试产出；“完成”的判断依据是可执行结果，不是看完资料。

| 天 | 学习 | 开发 | 当日产出与验收 |
|---|---|---|---|
| Day 1 | 岗位分层；Agent vs Workflow vs ChatBot | 项目选型、范围冻结、MVP 骨架 | 岗位分析、候选比较、5 tests 通过 |
| Day 2 | Tool Calling 消息协议、JSON Schema | 逐行理解 Agent 主循环；补参数类型校验 | 能画出两轮 Tool Calling 消息序列 |
| Day 3 | Prompt、结构化输出、上下文窗口 | 接入真实 LLM provider | 真实模型完成单工具与多工具调用 |
| Day 4 | RAG 在 LLM 应用体系中的位置 | 文档读取、清洗、Chunk 与元数据 | 3 类文档可稳定入库 |
| Day 5 | Embedding、相似度、向量索引 | 接入本地 Embedding 与向量检索 | 固定问题能返回正确来源 |
| Day 6 | Top-K、混合检索、Rerank 概念 | 建 20 条检索评测集，对比 BM25/向量 | 有命中率、延时数据和选型结论 |
| Day 7 | Memory 类型与 Token 预算 | 完善 SQLite 会话、窗口裁剪、会话隔离 | 多轮追问测试通过 |
| Day 8 | REST API、同步/异步边界 | FastAPI `/chat`、`/documents`、`/health` | API 测试通过，可用 curl 调用 |
| Day 9 | 失败模式、重试、幂等、超时 | 模型/工具异常、重试、日志字段 | 注入失败时系统可解释地退出 |
| Day 10 | Agent Evaluation | 建 Tool 选择与端到端评测脚本 | 输出成功率、失败分类、成本/延时 |
| Day 11 | LangGraph 封装了什么；MCP 是什么 | 只做一个小型对照实验或 MCP 适配 | 能明确说自己实现与框架实现差异 |
| Day 12 | 部署基本概念 | Streamlit 简单 UI；可选 Docker | 5～10 个真实案例可现场演示 |
| Day 13 | 项目表达与简历真实性 | 完善 README、学习指南、运行验证 | 简历描述与 30 秒/1/3 分钟介绍 |
| Day 14 | 五层面试题与系统设计 | 全新环境重装、回归测试、录演示 | 完成检查表；开始逐题模拟答辩 |

## 投递节奏

- 不等 Day 14 才开始看岗位：每天收藏并核验 3～5 个北京岗位。
- Day 7 有真实 LLM + RAG + tests 后可开始小批量投递，简历标注“持续迭代”。
- Day 10 有评测数据后更新简历与 GitHub；只写已经实际验证的数据。
- 算法训练型岗位与应用开发型岗位分两版简历，不用一个项目硬匹配所有方向。
