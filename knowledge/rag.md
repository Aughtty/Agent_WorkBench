# RAG 检索增强生成

RAG（Retrieval-Augmented Generation，检索增强生成）先从外部知识库检索相关内容，再把检索结果作为上下文交给大模型生成回答。它解决模型参数知识过时、私有知识缺失和答案难以追溯的问题。

典型流程是：文档解析、文本清洗、Chunk 切分、Embedding 向量化、写入 Vector Store、查询向量化、Top-K 检索、上下文拼接、模型生成和来源引用。

Chunk 太小会破坏上下文完整性并增加索引数量；Chunk 太大会混入无关信息、降低检索定位精度并占用更多上下文窗口。Overlap 用于保留相邻块边界上的语义，但过大也会产生重复结果。

Top-K 过小可能漏掉证据，过大则会加入噪声、消耗 Token，并可能干扰模型判断。应该通过固定问题集比较 Hit@K、MRR、回答质量、延时和成本，而不是凭感觉选择。

BM25 依赖词项匹配，适合专有名词和精确关键词；向量检索比较向量相似度，更适合表达不同但含义相关的内容；Hybrid Search 可以融合两者排名。检索正确不等于生成一定正确，因此 Retrieval 和 Generation 应分层评测。
